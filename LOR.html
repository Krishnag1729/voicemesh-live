What VoiceMesh is

You speak English into a cheap Android phone and hear Hindi speech back, usually within about a second of when you stop talking. The phone stays thin: it captures audio, sends only speech (an on-phone voice detector), compresses it and streams it. A server runs streaming speech recognition, translates clause by clause and speaks the Hindi, all on one shared consumer GPU. The aim was a design that a 2 GB phone and a single lab PC could sustain for hundreds of people.

Timeline: October–November 2026. It grew out of my earlier GPU streaming-ASR engine (GPU_Engine_ASR).

What I designed and built

  • Android client (Kotlin): Silero voice detection with hangover and pre-roll, Opus at ~16 kbit/s, WebSocket, jitter buffer. Shrunk from 35.3 to 7.1 MB using a custom ONNX Runtime build that contains only the detector's operators.
  • Gateway (Python asyncio): authentication, admission control at ≤85% predicted load, sticky routing, a 6 s replay buffer and resume tokens, so a worker crash doesn't lose speech.
  • GPU worker: cache-aware streaming FastConformer ASR batched across all users, a clause segmenter, IndicTrans2 translation with continuous batching, and Piper Hindi TTS with a TensorRT vocoder.
  • A deadline (EDF) GPU gate: translation and speech work waits whenever a speech-recognition tick has the earlier deadline, so recognition stays real time on a shared card.
  • Measurement harness: load generator, one-hour soak, accuracy and cost benchmarks, and a report generated only from the result files, so no number is typed by hand.

How I worked

  • Hypothesis, then measurement. Each milestone had one acceptance test written before the work (M0–M21). A failed hypothesis was recorded as a result. For example, I assumed the GPU was busy, but it was 71% idle, so the plan changed.
  • Gates fixed in advance. First audio ≤2.0 s p95, recognition-error change ≤0.2–0.5 points, and capacity counted only when every smaller user count also passed.
  • Honest statistics. Bootstrap confidence intervals for accuracy differences, repeated runs with different seeds, and soak tests rather than single short runs.
  • Negative results kept. The project log has 148 dated findings, including ideas that failed and corrections to my own earlier conclusions.
  • AI-assisted development, disclosed. An AI coding assistant (Claude Code) wrote and ran most of the code. I set the goals, chose the metrics and acceptance criteria, and made the design calls. The full development transcript is published.

Latest research, November 2026

Benchmark results on the same RTX 3050. These have not been through the real server yet and are not in the official report.

QuestionFinding
How many users fit under 2 s?320 (up from 210), three runs at 1.54–1.87 s, by compiling the recognition encoder with TensorRT and shortening its attention context from 70 to 40 frames
And under 4 s?340 held for a one-hour soak on a quiet machine; 360 is the ceiling and 380 fails
What does the shorter context cost?Nothing measurable on LibriSpeech (5.19 → 5.10%), but +0.68 points on Indian-accented speech (95% CI 0.15–1.20)
Would Whisper be better?Much more accurate on Indian accents (6.9% vs 22.7–26.2% word error on Svarah), but each live update takes 0.6–0.8 s on this GPU, so it can't serve many users. Fine-tuning the streaming model on Indian speech is the next step.
What else did I find?Main-process memory grows steadily in native code (~9 MB/min at 340 users), and other users' CPU jobs on a shared machine collapse latency. Both are open.
What didn't work?TensorRT for the translation decoder (slower), translation pacing, larger batches, more speech workers, a slot-style translation cache, a separate GPU process and translation priority

Known limits

  • Not yet tested on a real 2 GB Android Go phone, and radio energy use is unmeasured.
  • Recognition accuracy on Indian-accented English is the largest open risk (above).
  • Piper Hindi voices are research-only licences; a store release would use the system Hindi voice.
  • Cloud cost is extrapolated from the lab GPU, not measured on cloud hardware.
